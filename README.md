# SY-LAMP

Docker-окружение для локальной разработки на **Windows** с использованием Laravel и Drupal.

Проект создавался для личного использования и обучения: собрать удобное окружение, которое достаточно настроить один раз, а затем использовать для работы с разными PHP-проектами.

## Состав окружения

- **Docker Compose** — управление контейнерами.
- **Nginx** — веб-сервер и автоматическая маршрутизация проектов по локальным доменам.
- **PHP 8.3-FPM** — выполнение PHP-кода.
- **Composer 2** — управление PHP-зависимостями.
- **Xdebug** — отладка в IDE.
- **MySQL 8.0** — база данных.
- **phpMyAdmin** — веб-интерфейс управления базами данных.
- **Redis 7** — сервис для экспериментов с кешированием и другими сценариями.

## Быстрый запуск

### 1. Клонирование репозитория

```powershell
git clone https://github.com/SY-Soft/sy_lamp.git
cd sy_lamp
```

Для работы понадобятся установленный и запущенный Docker Desktop и PowerShell.

### 2. Запуск окружения

Перейдите в каталог `stack`:

```powershell
cd stack
```

Соберите PHP-образ и запустите контейнеры:

```powershell
docker compose up -d --build
```

### 3. Установка зависимостей проектов

Выполните команды из каталога `stack`:

```powershell
docker compose exec -w /var/www/projects/laravel php composer install
docker compose exec -w /var/www/projects/drupal php composer install
```

Composer установит зависимости согласно `composer.lock`. Исходные проекты и их конфигурация уже находятся в репозитории — создавать приложения заново не требуется.

После запуска и установки зависимостей доступны:

| Сервис | Адрес |
|---|---|
| Laravel | [http://laravel.localhost](http://laravel.localhost) |
| Drupal | [http://drupal.localhost](http://drupal.localhost) |
| phpMyAdmin | [http://localhost:8080](http://localhost:8080) |

Для phpMyAdmin используются демонстрационные учётные данные: **`root` / `root`**.

## Готовые демонстрационные проекты

В каталоге `projects` находятся два подготовленных проекта.

| Проект | Версия | Назначение |
|---|---|---|
| `projects/laravel` | Laravel 13 | Чистый демонстрационный проект Laravel |
| `projects/drupal` | Drupal 11 | Чистый демонстрационный проект Drupal |

Для Drupal предусмотрена демонстрационная учётная запись: **`admin` / `admin`**.

### О версиях и совместимости

Указанные версии относятся к проектам, которые подготовлены в репозитории:

- Laravel использует ограничение `^13.17` в `composer.json`.
- Drupal использует `drupal/core-recommended` с ограничением `^11.4`.
- PHP в окружении — 8.3.

Это **не список всех поддерживаемых версий фреймворков**. Окружение может использоваться и с другими проектами, но совместимость их версий Laravel, Drupal, PHP и сторонних пакетов необходимо проверять отдельно. Одного запуска Docker недостаточно, чтобы гарантировать работоспособность произвольного проекта.

## Автоматические домены

Nginx определяет проект по имени каталога внутри `projects`:

- `projects/laravel` → `http://laravel.localhost`
- `projects/drupal` → `http://drupal.localhost`

Для дополнительного проекта, например `projects/myproject`, предусмотрен домен `http://myproject.localhost`.

В зависимости от структуры проекта Nginx использует каталог `public` или `web` в качестве корня сайта. Это позволяет работать с типичной структурой Laravel и Drupal без отдельной конфигурации виртуального хоста для каждого проекта.

## Composer и Artisan

Для удобства в проектах предусмотрены локальные BAT-файлы-обёртки, позволяющие запускать Composer и Artisan внутри PHP-контейнера.

Находясь в каталоге нужного проекта, можно выполнять команды:

```powershell
.\composer --version
.\composer install
.\composer require vendor/package

.\artisan about
.\artisan migrate
```

Обёртки избавляют от необходимости каждый раз вводить полную команду `docker compose exec`.

Подробности создания и настройки проектов приведены в инструкциях:

- [Установка Laravel](docs/laravel.md)
- [Установка Drupal](docs/drupal.md)

## Xdebug и PhpStorm

Xdebug настроен на запуск отладки по триггеру:

```ini
xdebug.mode=debug
xdebug.start_with_request=trigger
xdebug.client_host=host.docker.internal
xdebug.client_port=9003
```

В PhpStorm необходимо настроить сервер отладки и сопоставление локальных файлов проекта с каталогом внутри контейнера `/var/www/projects/ИМЯ_ПРОЕКТА`.

Для запуска отладки используется триггер `XDEBUG_TRIGGER=1`.

## Данные MySQL и перенос окружения

Каталог `mysql` хранится непосредственно в репозитории и подключается к контейнеру MySQL как каталог данных. Поэтому подготовленные демонстрационные базы данных переносятся вместе с проектом.

Такой подход упрощает развёртывание на другом компьютере: не нужно отдельно импортировать SQL-дампы для восстановления демонстрационного состояния.

При этом каталог MySQL содержит физические файлы базы данных, а не универсальный переносимый дамп. Его состояние зависит от версии и настроек MySQL. Не следует произвольно удалять или исключать отдельные файлы из этого каталога.

## Быстрый запуск и восстановление MySQL

Вместо ручного запуска можно использовать PowerShell-скрипт из каталога `stack`:

```powershell
.\start.ps1
```

Скрипт проверяет наличие основных файлов инициализации MySQL. Если каталог данных выглядит инициализированным, он запускает окружение. Если каталог отсутствует или не проходит проверку, скрипт выполняет повторную инициализацию MySQL.

**Внимание:** при повторной инициализации содержимое каталога `mysql` удаляется. Это может привести к потере существующих баз данных. Скрипт не восстанавливает ранее сохранённые пользовательские данные.

Не запускайте его автоматически при любой ошибке MySQL. Перед восстановлением убедитесь, что существующие данные не нужны либо у вас есть их резервная копия.

Дополнительные инструкции по диагностике и восстановлению приведены в документе [Запуск и восстановление окружения](docs/start.md).

## Особенности учебного репозитория и безопасность

Этот репозиторий **умышленно отступает от некоторых стандартных рекомендаций по организации production-репозиториев**.

Для упрощения развёртывания и обучения в него включены демонстрационные настройки, учётные данные и подготовленные физические данные MySQL. В частности, в репозитории сохранены конфигурация Laravel `.env`, настройки Drupal `settings.php` и демонстрационные базы данных.

Это сделано намеренно: после клонирования начинающий разработчик может быстрее получить работающую среду, изучать код, Docker, PHP и взаимодействие приложений с базами данных, не проходя дополнительную настройку секретов и импорт баз с нуля.

При этом необходимо учитывать следующие ограничения:

- **Окружение предназначено для локальной разработки и обучения, а не для production.**
- Пароли `root` / `root` и `admin` / `admin` являются демонстрационными и не должны использоваться на реальных серверах.
- В конфигурации присутствуют настройки, рассчитанные на этот Docker-стек; их нельзя без проверки переносить в другое окружение.
- Порты веб-сервера, MySQL и phpMyAdmin опубликованы на хосте. Используйте окружение на доверенном компьютере и в доверенной сети; не открывайте доступ к нему в публичный интернет.
- Не помещайте в этот репозиторий реальные пароли, пользовательские данные или базы данных рабочих систем.

Для production необходимо отдельно настроить секреты, учётные записи и права доступа к базам данных, сетевую доступность сервисов, резервное копирование и остальные меры безопасности.
